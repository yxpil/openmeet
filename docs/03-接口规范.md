# OpenMeet 接口规范

> 协议版本：`1` ｜ API 前缀：`/api` ｜ WebSocket：`/ws` ｜ 最后更新：2026-10-22

本文件是实现与测试的契约。字段名使用 camelCase；时间为 Unix 毫秒（除特别注明）；令牌均为字符串。

## 1. 通用约定

### 1.1 请求与响应

- REST：`Content-Type: application/json`；请求体上限 64 KiB。
- 认证：`Authorization: Bearer <accessToken>`。
- 成功：`200/201` 返回 JSON；`204` 无正文。
- 失败：`{ "error": { "code": "string", "message": "string" } }`。
- 所有未知字段忽略；类型不符返回 `invalid_request`。
- CORS：默认 `Access-Control-Allow-Origin: *`，允许 `Authorization, Content-Type`；
  可配置为白名单。不依赖 Cookie。
- 响应头包含 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、
  `X-Frame-Options: DENY`。

### 1.2 错误码

| code | 典型 HTTP | 含义 |
| --- | --- | --- |
| `invalid_request` | 400 | 字段缺失/格式错误/超长 |
| `unauthorized` | 401 | 缺少或无效访问令牌 |
| `invalid_credentials` | 401 | 账号或密码错误 |
| `invalid_token` | 401 | 令牌过期/被吊销/重放 |
| `password_required` | 401 | 房间需要密码 |
| `wrong_password` | 403 | 房间密码错误 |
| `forbidden` | 403 | 权限不足 |
| `invite_required` | 403 | 嘉宾缺少邀请令牌 |
| `invalid_invite` | 403 | 邀请令牌无效 |
| `guests_disabled` | 403 | 服务器禁止访客 |
| `registration_closed` | 403 | 注册关闭 |
| `lan_mode` | 403 | 局域网模式不提供该接口 |
| `room_not_found` | 404 | 房间不存在 |
| `room_ended` | 410 | 房间已结束 |
| `room_locked` | 403 | 房间已锁定 |
| `room_full` | 409 | 人数已满 |
| `username_taken` | 409 | 用户名已存在 |
| `rate_limited` | 429 | 请求过于频繁 |
| `payload_too_large` | 413 | 请求体超限 |
| `not_found` | 404 | 路由不存在 |
| `internal_error` | 500 | 服务器内部错误 |
| `protocol_error` | WS | 消息格式错误/首包非 hello |
| `not_admitted` | WS | 等候室成员尝试会议操作 |
| `unknown_peer` | WS | 目标成员不存在 |

### 1.3 限流

| 场景 | 规则 |
| --- | --- |
| 登录 | 10 次 / 10 分钟 / (IP, username) |
| 注册 | 5 次 / 小时 / IP |
| 加入房间 | 30 次 / 分钟 / IP |
| WS 消息 | 60 条 / 10 秒 / 连接 |
| WS 聊天 | 5 条 / 5 秒 / 连接 |

## 2. REST 接口

### 2.1 服务器信息

`GET /api/server`（公开）

```json
{
  "name": "OpenMeet Server",
  "version": "0.1.0",
  "protocol": 1,
  "mode": "server",
  "registration": "open",
  "guests": true,
  "maxParticipants": 12
}
```

- `mode`: `server | lan`。
- `registration`: `open | closed`。
- `guests`: 是否允许访客加入。
- `maxParticipants`: 本服务器允许的房间人数上限。

### 2.2 健康检查

`GET /api/health`（公开）

```json
{ "ok": true, "version": "0.1.0", "uptimeSec": 123 }
```

### 2.3 注册

`POST /api/auth/register`

```json
{ "username": "alice", "password": "correct horse battery", "displayName": "Alice" }
```

- username：3–32，`^[a-zA-Z0-9_.-]+$`，大小写不敏感，统一存小写。
- password：8–128。
- displayName：可选，1–40，默认 username。

`201`：

```json
{
  "user": { "id": "u_...", "username": "alice", "displayName": "Alice", "role": "user", "createdAt": 1760000000000 },
  "accessToken": "eyJ...",
  "refreshToken": "b64url...",
  "expiresIn": 1200
}
```

错误：`registration_closed`、`username_taken`、`rate_limited`、`invalid_request`。

### 2.4 登录

`POST /api/auth/login`

```json
{ "username": "alice", "password": "correct horse battery" }
```

`200`：同注册响应。
错误：`invalid_credentials`、`rate_limited`、`invalid_request`。

### 2.5 刷新令牌

`POST /api/auth/refresh`

```json
{ "refreshToken": "b64url..." }
```

`200`：`{ accessToken, refreshToken, expiresIn, user }`

- 每次刷新都轮换 refreshToken，旧的立即失效。
- 使用已吊销令牌：该用户全部刷新令牌失效，返回 `invalid_token`。

### 2.6 登出

`POST /api/auth/logout`

```json
{ "refreshToken": "b64url..." }
```

`204`（即使令牌不存在也返回 204）。

### 2.7 当前用户

`GET /api/auth/me`（Bearer）→ `{ "user": User }`

`PATCH /api/auth/me`（Bearer）

```json
{ "displayName": "Alice W." }
```

→ `{ "user": User }`。displayName 1–40。

### 2.8 创建房间

`POST /api/rooms`（Bearer）

```json
{
  "title": "周一产品同步",
  "password": "1234",
  "lobby": true,
  "maxParticipants": 6,
  "dialIn": "+86215550100"
}
```

- title：1–80。
- password：可选，4–64；省略或空串表示无密码。
- lobby：可选，默认 `false`。
- maxParticipants：可选，2..服务器上限，默认 8。
- dialIn：可选。规范化后 3–32 位，允许 `+` 前缀、数字与字母，空格/括号/连字符/点会被剔除。
  在**进行中的房间**内唯一，重复返回 `409 dial_in_taken`，非法返回 `400 invalid_request`。
  只有部署了互通网关时才有意义。

`201`：

```json
{
  "room": {
    "id": "r_...",
    "code": "K7M2Q9X4B",
    "title": "周一产品同步",
    "kind": "server",
    "locked": false,
    "lobby": true,
    "maxParticipants": 6,
    "hostPeerId": null,
    "dialIn": "+86215550100",
    "createdAt": 1760000000000,
    "status": "active"
  },
  "ticket": "eyJ...",
  "self": { "userId": "u_...", "displayName": "Alice", "guest": false, "host": true },
  "ice": {
    "iceServers": [{ "urls": ["stun:stun.l.google.com:19302"] }],
    "iceTransportPolicy": "all"
  },
  "inviteToken": "b64url-32-bytes"
}
```

房间在创建后即开始空房计时（15 分钟），主持者应在有效期内用 ticket 连接 `/ws`。

### 2.9 我的会议

`GET /api/rooms/mine?limit=30`（Bearer）

```json
{ "rooms": [ RoomSummary ] }
```

- 返回该用户主持或（以注册用户身份）参加过的房间，按创建时间倒序。
- `limit` 1..100，默认 30。
- `participantCount` 为曾准入的参会记录数（包含访客，同一用户多设备会重复计数）。

### 2.9.1 网关拨入解析

`POST /api/gateway/resolve`

请求头 `x-openmeet-gateway: <OPENMEET_GATEWAY_TOKEN>`（与服务器常量时间比较）。
未配置该环境变量时接口一律 `401 gateway_unauthorized`，即默认关闭。

```json
{ "number": "+86215550100", "displayName": "电话接入(13800000000)" }
```

`200` 与 `POST /api/rooms/:code/join` 同构（`ticket / room / self / ice`），语义是：
网关作为受信基础设施替主叫换取入会票据，因此**跳过房间密码**，但房间锁定、人数上限
与等候室仍然生效（等候室内主叫需主持者准入）。

| 情况 | 响应 |
| --- | --- |
| 缺少或错误的网关头 | `401 gateway_unauthorized` |
| 号码格式非法 | `400 invalid_request` |
| 没有进行中的房间使用该号码 | `404 room_not_found` |
| 房间已锁定 | `403 room_locked` |
| 人数已满 | `409 room_full` |

`displayName` 省略时为「电话接入」；主叫号码由网关拼在括号里，便于主持者在参会者列表里
识别来电。局域网模式不提供该接口（`403 lan_mode`）。

### 2.10 加入房间

`POST /api/rooms/:code/join`

`:code` 可带分隔符，服务端规范化。

请求头：可选 `Authorization: Bearer <accessToken>`。

```json
{
  "displayName": "Bob",
  "password": "1234",
  "inviteToken": "b64url..."
}
```

规则：

- 已登录用户：无需邀请令牌；`displayName` 可省略（使用账号显示名）。
- 访客：必须提供 `inviteToken` 与 `displayName`（1–40）；服务器需允许访客。
- 房间密码：主持者免验；其余人必须提供正确密码。
- 房间锁定：主持者外一律 `room_locked`。
- 容量：含等候成员，满则 `room_full`；主持者不受容量限制。
- 会议已结束时：只有**原主持者**的加入会把该房间按原配置重新开启（同房间号、同标题、
  同密码与人数上限，`locked` 归零，历史参与记录保留），其他人仍得到 `room_ended`。
  这让"结束后自动等待重开"有确定的对象，而不是凭空的猜测。
- 成功即签发 join ticket；访客/等候室资格在 WS `welcome` 中体现。

`200`：

```json
{
  "ticket": "eyJ...",
  "room": RoomView,
  "self": { "userId": "u_...", "displayName": "Bob", "guest": false, "host": false },
  "ice": IceConfig,
  "inviteToken": "仅主持者返回"
}
```

错误：`room_not_found`、`room_ended`、`room_locked`、`room_full`、
`password_required`、`wrong_password`、`invite_required`、`invalid_invite`、
`guests_disabled`、`unauthorized`（提供了无效 Bearer）。

### 2.11 局域网加入

`POST /api/lan/join`（仅 `mode=lan` 的内嵌服务器）

```json
{
  "roomId": "r_...",
  "inviteToken": "b64url...",
  "displayName": "Bob",
  "password": "1234"
}
```

`200`：同加入房间响应（不返回 `inviteToken`）。

错误：`lan_mode`（非 LAN 模式）、`invite_required`、`invalid_invite`、
`password_required`、`wrong_password`、`room_locked`、`room_full`、`room_ended`。

> LAN 模式不提供 `/api/auth/*`、`/api/rooms`；创建房间由桌面主进程通过 IPC 直接调用
> 内嵌服务内核，不暴露在网络接口上。

## 3. WebSocket 信令

### 3.1 连接与握手

- URL：`ws(s)://<server>/ws`（无查询参数）。
- 首条消息必须是 `hello`，10 秒内未收到则关闭。
- 握手成功后服务端分配 `peerId`；每个连接仅属于一个房间。
- 单帧上限 128 KiB。
- 客户端发送应用层 `ping` 每 25 秒；服务端 75 秒无任何消息则断开。
- 重连使用同一 ticket，获得新的 `peerId`，需要重建 PeerConnection。

`hello`（客户端 → 服务端）：

```json
{ "type": "hello", "v": 1, "ticket": "eyJ..." }
```

服务端校验：JWT 签名/过期、`typ=join`、房间存在、ticket 中 `roomId` 匹配、
连接未被封禁。版本不符 → `error(protocol_error)` + close `4001`。
ticket 无效 → close `4002`。房间已结束 → close `4003`。

### 3.2 客户端 → 服务端消息

| type | 载荷 | 约束 |
| --- | --- | --- |
| `hello` | `v:number, ticket:string` | 仅一次，首包 |
| `signal` | `to:peerId, data:SignalData` | 仅已准入；目标同房间 |
| `media` | `state:MediaState` | 完整快照，4 个布尔 |
| `chat` | `text:string, clientId?:string` | 1–2000 字符，仅已准入 |
| `lobby.admit` | `peerId:string` | host/cohost |
| `lobby.deny` | `peerId:string` | host/cohost |
| `room.lock` | `locked:boolean` | host/cohost |
| `room.kick` | `peerId:string` | host/cohost，受角色约束 |
| `room.mute` | `peerId:string` | host/cohost，受角色约束 |
| `room.role` | `peerId:string, role:'cohost'\|'participant'` | 仅 host |
| `room.end` | `{}` | 仅 host（主持空缺时 cohost） |
| `room.leave` | `{}` | 任意已准入成员 |
| `ping` | `t:number` | 任意时刻 |

`SignalData`：

```ts
type SignalData =
  | { kind: 'offer';  sdp: string }
  | { kind: 'answer'; sdp: string }
  | { kind: 'candidate'; candidate: {
        candidate: string;
        sdpMid?: string | null;
        sdpMLineIndex?: number | null;
        usernameFragment?: string | null;
      } };
```

SDP ≤ 96 KiB；candidate ≤ 4 KiB；服务端不解析 SDP 内容，只做长度与结构校验后定向转发。

### 3.3 服务端 → 客户端消息

| type | 载荷 |
| --- | --- |
| `welcome` | `self, room, participants[], pending[], admitted` |
| `admitted` | `room, participants[]` |
| `lobby.request` | `peer: PendingJoin` |
| `lobby.update` | `pending: PendingJoin[]`（发给主持/联席，等候列表变化时） |
| `lobby.denied` | `reason?: string` |
| `peer.join` | `peer: Participant` |
| `peer.leave` | `peerId, reason:'left'\|'kicked'\|'disconnected'` |
| `peer.update` | `peerId, state, role?` |
| `room.update` | `room: RoomView` |
| `signal` | `from: peerId, data: SignalData` |
| `chat` | `message: ChatMessage` |
| `moderation` | `action:'muted'\|'kicked'\|'role', byName?, role?, reason?` |
| `room.ended` | `reason:'host_ended'\|'empty'\|'server_shutdown'\|'host_left', byName?` |
| `pong` | `t:number` |
| `error` | `code, message, request?` |

`welcome` 示例（直接准入，本人不在 `participants` 中）：

```json
{
  "type": "welcome",
  "self": {
    "peerId": "p_...",
    "userId": "u_...",
    "name": "Bob",
    "role": "participant",
    "guest": false,
    "admitted": true
  },
  "room": RoomView,
  "participants": [ Participant ],
  "pending": [],
  "admitted": true
}
```

- 等候室成员：`admitted=false`，`participants=[]`、`pending=[]`，不暴露成员名单。
- 主持者：`admitted=true`，`pending` 为当前等候列表。
- `admitted` 消息中的 `participants` 为**其他**已准入成员；被准入者据此向每人发起 offer。
- 主持断线 45 秒内 `room.hostPeerId` 为 `null`，宽限后广播 `room.update`。

### 3.4 关键时序

**等候室**

1. 嘉宾 hello → server `welcome(admitted=false)`。
2. host 收到 `lobby.request`。
3. host `lobby.admit` → 嘉宾 `admitted(participants)`，其他成员 `peer.join`。
4. host `lobby.deny` → 嘉宾 `lobby.denied` 并 close `4004`。

**主持移交**

1. host 连接断开 → 其他成员收到 `peer.leave(reason=disconnected)`，`room.hostPeerId=null`。
2. 45 秒内 host 重连（ticket 中 host=true）→ `room.update` 恢复。
3. 超时：选一位 cohost（最早加入）或最早加入的 participant 为新 host；
   广播 `peer.update(role=host)` 与 `room.update`。

**结束**

1. host `room.end` → 所有人 `room.ended`，随后 close `4003`；房间销毁、写库。
2. 空房 15 分钟 → 同样结束，reason=`empty`。

### 3.5 关闭码

| code | 含义 |
| --- | --- |
| `1000` | 正常关闭 |
| `4001` | 协议版本不符/hello 超时 |
| `4002` | ticket 无效/过期 |
| `4003` | 房间已结束/不存在 |
| `4004` | 被移出、被拒绝或封禁 |
| `4005` | 触发限流 |
| `4006` | 消息格式错误 |
| `4007` | 服务器关闭 |
| `4008` | 认证阶段重复 hello / 非法状态 |

客户端收到 4001–4004 不再自动重连；其他情况退避重连（最多 5 次）。

## 4. Join Ticket

JWT HS256，`typ=join`：

```json
{
  "typ": "join",
  "sub": "u_... 或 guest_...",
  "sid": "随机会话 ID",
  "name": "Bob",
  "roomId": "r_...",
  "code": "K7M2Q9X4B",
  "guest": false,
  "userId": "u_...",
  "host": false,
  "iat": 1760000000,
  "exp": 1760014400,
  "jti": "..."
}
```

- 有效期 4 小时；只在内存与 IPC 中传递，不写 URL。
- `host=true` 表示持有房间创建凭证；若已有其他 host 在线，则降级为 cohost。
- 重连时同一 ticket 复用 `sid`，已准入资格保留；被踢/被拒后 `sid` 加入封禁集合。

## 5. 邀请载荷

### 5.1 文本格式

```
OM1.<base64url(UTF-8 JSON)>
```

复制给用户的完整文本建议：

```
OpenMeet 邀请你加入会议
主题：周一产品同步
房间码：K7M-2Q9-X4B
OM1.eyJ2IjoxLCJraW5kIjoic2VydmVyIiw...
```

解析时在文本中查找 `OM1\.[A-Za-z0-9_-]+`，忽略前后说明文字。

### 5.2 JSON 结构

```ts
interface InvitePayload {
  v: 1;
  kind: 'server' | 'lan';
  title: string;        // ≤ 80
  code: string;         // 9 位房间码，服务端规范化
  token: string;        // 邀请令牌，base64url，20–128
  server?: string;      // kind=server：http(s) 基础地址，不含路径
  rid?: string;         // kind=lan：房间 ID
  endpoints?: string[]; // kind=lan：HTTP 基础地址（含端口），最多 12 个
}
```

规则：

- `server`：必须 `http:`/`https:`，去尾斜杠；不支持子路径部署。
- `endpoints`：`http:` 地址；受邀端并发探测 `/api/lan/join`。
- 载荷只编码一次，不允许嵌套邀请。
- 邀请令牌等价于进门能力；UI 提示不要公开转发。

### 5.3 邀请令牌生成

```
inviteToken = base64url(HMAC-SHA256(inviteSecret, "invite:" + roomId))
```

- 远程服务端 `inviteSecret` 由 JWT secret 派生；LAN 模式为进程随机值。
- 房间结束或服务端重启后令牌自然失效。

## 6. ICE / TURN

### 6.1 下发格式

create/join 响应中的 `ice` 字段遵循浏览器 `RTCConfiguration` 子集：

```json
{
  "iceServers": [
    { "urls": ["stun:stun.l.google.com:19302"] },
    { "urls": ["turn:turn.example.com:3478?transport=udp"], "username": "1760003600:u_123", "credential": "base64hmac" }
  ],
  "iceTransportPolicy": "all"
}
```

客户端设置可覆盖：自定义 STUN/TURN 时**追加**到服务器列表；`relayOnly` 开启时
使用 `iceTransportPolicy: "relay"`。

### 6.2 coturn 短时凭据（推荐）

服务端配置共享密钥 `TURN_SECRET` 与 `TURN_URLS`：

```
username   = "<expiryUnixSeconds>:<identity>"
credential = base64(HMAC-SHA1(TURN_SECRET, username))
ttl        = 12h
```

coturn 需配置 `use-auth-secret`、`static-auth-secret=<TURN_SECRET>`。
`identity` 为 userId 或 `guest-<random>`，不包含个人信息。

### 6.3 内嵌 TURN

- `TURN_MODE=embedded`：使用 `node-turn`，UDP 监听 3478，
  `authMech=long-term`，静态 `TURN_USERNAME/TURN_PASSWORD`。
- 需要 `TURN_PUBLIC_HOST` 生成可访问的 `turn:` URL；缺失则启动失败。
- 仅建议临时/小规模使用；生产使用 coturn。

## 7. 服务端兼容性

- `GET /api/server` 返回 `protocol: 1`。
- 客户端要求完全匹配主版本；不匹配时显示“服务器版本不兼容”，不进行握手。
- 新增可选字段不提升版本；删除/改名字段、改变语义才提升版本。

## 8. Electron IPC 契约

渲染层只能通过预加载暴露的 `window.openmeet` 访问主进程（`contextIsolation` 开启、
`nodeIntegration` 关闭、`sandbox` 开启）。通道名定义在 `packages/desktop/src/shared/ipc.ts`。

### 8.2 事件型通道（主进程 → 渲染层）

| 通道 | 载荷 | 触发时机 |
| --- | --- | --- |
| `window:state` | `{maximized: boolean}` | 窗口最大化/还原 |
| `deep-link` | `url: string` | 系统用 `openmeet://` 唤起应用；启动前的链接会在页面加载完成后补发 |
| `scheduled:reminder` | `ScheduledJoinRecord` | 入会前 60 秒提醒一次，渲染层提供「取消」 |
| `scheduled:join` | `ScheduledJoinEvent` | 到点执行；此时才附带解密后的 `password`，或 `passwordUnavailable: true` |
| `scheduled:missed` | `ScheduledJoinRecord` | 应用未运行期间已过的预约，直接丢弃，不补开 |
| `p2p:event` | `{kind:'peers'\|'signal'\|'chat'\|'left'\|'fatal', …}` | 无服务器直连的唯一事件通道；单通道带标签以保证顺序 |

深链格式：`openmeet://join?invite=<OM1...>`。渲染层依次尝试 `invite`、`data`、`text`
查询参数、路径本体，最后用 `OM1\.[A-Za-z0-9_-]+` 兜底提取，再交给统一的邀请解码流程。

窗口控制 `window:minimize` / `window:maximize` / `window:close` 为单向 `send`。

### 8.4 定时入会

```ts
type ScheduledJoinKind = 'server' | 'lan' | 'p2p';

type ScheduledJoinRecord = {
  id: string;              // sj_<uuid>，主进程生成
  kind: ScheduledJoinKind; // 加入服务器会议 / 主持局域网会议 / 无服务器直连
  serverUrl: string;       // 归一化后的 http(s) origins；非 server 类为空串
  roomCode: string;        // server：9 位房间号；p2p：自定义会议号；lan：留空（触发时才有）
  roomTitle: string;       // ≤ 80 字符，留空时按 kind 生成默认标题
  displayName: string;     // 1–40 字符
  at: number;              // 入会时刻，Unix 毫秒，本地时钟
  createdAt: number;
  hasPassword: boolean;
  passwordFormat: 'safeStorage-v1' | 'plain-v0';
  lobby: boolean;          // 仅 kind='lan'：主持时是否开等候室
  maxParticipants: number; // 仅 kind='lan'：2–12
};

type ScheduledJoinEvent = ScheduledJoinRecord & {
  password?: string;             // 仅 scheduled:join，解密后才带上；p2p 时即口令
  passwordUnavailable?: boolean; // 存了密码但当前无法解密
};
```

校验规则集中在 `packages/desktop/src/main/scheduled.ts`，`scheduledCreate` 与单元测试共用同一份实现：

| 规则 | 值 |
| --- | --- |
| 房间号 | `server`：归一化后匹配 `^[A-Z0-9-]{4,16}$`；`p2p`：`^[A-Z0-9]{4,16}$`（自定义会议号，不受服务器 9 位规则约束）；`lan`：无需填写 |
| 服务器 | `server` 必须 `^https?://.+` 并按 `normalizeServerUrl` 归一化；其它 kind 不校验 |
| 显示名称 | 1–40 个字符 |
| 入会时间 | 必须晚于当前时间，且不超过 90 天 |
| 预约数量 | 每机最多 50 条 |
| 房间密码 / 口令 | ≤ 64 字符，与刷新令牌同样走 `safeStorage`；不可用时降级为 `plain-v0` 并在记录中标注 |

约定：列表接口一律**不返回密码**，密码只在 `scheduled:join` 触发的那一刻解密；一条预约触发一次即作废，
应用未运行期间已过的预约按 `scheduled:missed` 丢弃而不是迟到补开。
