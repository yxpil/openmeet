# OpenMeet 服务端部署与运维

> 适用于 `@openmeet/server` v0.1 ｜ Node.js ≥ 22.5 ｜ 最后更新：2026-10-22

## 1. 运行要求

- Node.js ≥ 22.5（必须包含稳定的 `node:sqlite`；推荐 Node 24 LTS）。
- 无原生编译依赖；`ws` 为纯 JS，内嵌 TURN 为可选纯 JS 依赖。
- 可写数据目录；单个 TCP 端口（默认 8787）。
- 跨公网使用建议配置 TLS 反向代理；局域网部署可直接 HTTP。

## 2. 安装与启动

### 2.1 从源码（推荐）

```bash
git clone <your-fork-url> openmeet
cd openmeet
npm ci
npm run build:server

export OPENMEET_DATA_DIR=/var/lib/openmeet
export OPENMEET_PORT=8787
export OPENMEET_REGISTRATION=open
npm run start:server
```

打开桌面端，服务器地址填写 `http://<host>:8787`，注册首个账号。
注册完成后建议把 `OPENMEET_REGISTRATION` 改为 `closed` 并重启。

开发模式：

```bash
npm run dev:server
# 另开终端
npm run dev:desktop
```

### 2.2 仅安装服务端 workspace

在与桌面端同仓库时：

```bash
npm ci --workspace @openmeet/server --include-workspace-root
npm run build:server
```

### 2.3 Docker

仓库提供 `Dockerfile` 与 `docker-compose.yml`：

```bash
docker compose up -d --build
```

默认映射 8787/tcp，数据放在命名卷 `openmeet-data`（容器内 `/var/lib/openmeet`，
以非 root 用户运行）。生产请在前方加 TLS 反向代理，
并按需开启 TURN（见第 5 节）。

## 3. 配置项

所有配置通过环境变量。未设置的密钥会生成并持久化到数据目录。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `OPENMEET_HOST` | `::` | 监听地址，默认双栈；失败回退 `0.0.0.0` |
| `OPENMEET_PORT` | `8787` | HTTP/WS 端口，`0` 表示随机 |
| `OPENMEET_DATA_DIR` | `./data` | 数据目录；SQLite 与密钥文件 |
| `OPENMEET_DB_PATH` | `<data>/openmeet.db` | 可覆盖数据库路径 |
| `OPENMEET_SERVER_NAME` | `OpenMeet Server` | 登录页显示名称 |
| `OPENMEET_PUBLIC_URL` | 空 | 对外基础 URL，仅用于展示/文档 |
| `OPENMEET_JWT_SECRET` | 自动生成 | HS256 密钥（≥ 32 字符），生成后保存为 `jwt-secret` |
| `OPENMEET_REGISTRATION` | `open` | `open`/`closed` |
| `OPENMEET_ALLOW_GUESTS` | `true` | 是否允许持邀请的访客 |
| `OPENMEET_MAX_PARTICIPANTS` | `12` | 房间人数上限（硬上限） |
| `OPENMEET_ALLOWED_ORIGINS` | `*` | CORS 允许源，逗号分隔 |
| `OPENMEET_TRUST_PROXY` | `false` | 信任 `X-Forwarded-For`（仅置于可信代理后） |
| `OPENMEET_STUN_URLS` | `stun:stun.l.google.com:19302` | 逗号分隔；置空可关闭 |
| `OPENMEET_LOG_LEVEL` | `info` | `debug`/`info`/`warn`/`error` |
| `OPENMEET_TURN_MODE` | `off` | `off`/`embedded`/`coturn` |
| `OPENMEET_TURN_PORT` | `3478` | 内嵌 TURN UDP 端口 |
| `OPENMEET_TURN_PUBLIC_HOST` | 空 | 内嵌 TURN 对外可解析主机名/IP |
| `OPENMEET_TURN_USERNAME` | 空 | 内嵌 TURN 静态用户名 |
| `OPENMEET_TURN_PASSWORD` | 空 | 内嵌 TURN 静态密码 |
| `OPENMEET_TURN_REALM` | `openmeet` | TURN realm |
| `OPENMEET_TURN_SECRET` | 空 | coturn `static-auth-secret` |
| `OPENMEET_TURN_URLS` | 空 | coturn 下发的 TURN URL，逗号分隔 |
| `OPENMEET_TURN_TTL` | `43200` | coturn 短时凭据有效期（秒） |

示例：

```bash
OPENMEET_JWT_SECRET="$(openssl rand -base64 48)" \
OPENMEET_REGISTRATION=closed \
OPENMEET_ALLOW_GUESTS=true \
OPENMEET_STUN_URLS="stun:stun.example.com:3478" \
OPENMEET_TURN_MODE=coturn \
OPENMEET_TURN_URLS="turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp" \
OPENMEET_TURN_SECRET="shared-secret-with-coturn" \
node packages/server/dist/index.mjs
```

## 4. 反向代理与 TLS

### 4.1 Caddy（推荐）

```caddyfile
meet.example.com {
  encode zstd gzip
  reverse_proxy 127.0.0.1:8787
}
```

Caddy 自动处理证书与 WebSocket 升级。客户端服务器地址填写 `https://meet.example.com`。

### 4.2 Nginx

```nginx
server {
  listen 443 ssl http2;
  server_name meet.example.com;

  ssl_certificate     /etc/letsencrypt/live/meet.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/meet.example.com/privkey.pem;

  client_max_body_size 128k;

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 3600s;
  }
}
```

```nginx
map $http_upgrade $connection_upgrade {
  default upgrade;
  ''      close;
}
```

启用 `OPENMEET_TRUST_PROXY=true` 以获得正确的客户端 IP（用于限流），
但仅能在可信代理之后启用。**不支持部署在子路径**（如 `/openmeet/`）。

Electron 默认拒绝不受信任的自签名证书。若内网使用自签名证书，
需把根证书安装到操作系统的受信任根存储；否则请用受信任证书或服务端直连 HTTP（仅限内网）。

## 5. TURN 桥接

WebRTC 在对称 NAT 或 UDP 封锁时依赖 TURN。两种模式：

### 5.1 内嵌 node-turn（快速）

```bash
OPENMEET_TURN_MODE=embedded \
OPENMEET_TURN_PUBLIC_HOST=turn.example.com \
OPENMEET_TURN_USERNAME=openmeet \
OPENMEET_TURN_PASSWORD='strong-password' \
OPENMEET_TURN_PORT=3478 \
npm run start:server
```

- 需要安装可选依赖 `node-turn`（`npm ci` 默认会装；可 `npm install node-turn`）。
- 仅 UDP；静态凭据；无 TLS/TCP 回退。适合小规模或临时使用。
- 防火墙放行 `3478/udp` 与中继端口范围 `49152–65535/udp`。
- 公网 TURN 必须配置可访问的 `OPENMEET_TURN_PUBLIC_HOST`，否则服务启动失败。

### 5.2 coturn（生产推荐）

`/etc/turnserver.conf` 关键项：

```ini
listening-port=3478
tls-listening-port=5349
fingerprint
use-auth-secret
static-auth-secret=<与 OPENMEET_TURN_SECRET 一致>
realm=turn.example.com
min-port=49160
max-port=49200
no-multicast-peers
no-cli
cert=/etc/letsencrypt/live/turn.example.com/fullchain.pem
pkey=/etc/letsencrypt/live/turn.example.com/privkey.pem
```

OpenMeet 配置：

```bash
OPENMEET_TURN_MODE=coturn
OPENMEET_TURN_SECRET=<同上>
OPENMEET_TURN_URLS="turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp,turns:turn.example.com:5349?transport=tcp"
```

凭据算法：`username="<expiry>:<identity>"`，`credential=base64(HMAC-SHA1(secret, username))`，
每次 join/create 动态下发。

### 5.3 验证

1. 客户端设置中开启“仅中继（桥接）”。
2. 加入会议，双方应能互联；调用 `chrome://webrtc-internals`（开发构建）查看
   选中的 candidate pair 类型为 `relay`。
3. 若失败：检查 TURN URL 可达、凭据有效期、UDP/TCP 端口与防火墙、coturn 日志。

## 6. 防火墙与端口

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 8787（或反代 443） | TCP | HTTP API + WebSocket |
| 3478 | UDP | 内嵌 TURN |
| 49152–65535 | UDP | 内嵌 TURN 中继（或 coturn 自定义范围） |
| 45871（默认，可能顺延） | TCP | 客户端 LAN 模式内嵌信令（仅主机） |

- 媒体 P2P 使用客户端出站 UDP，无需在服务器开放。
- 启用 IPv6 时确认防火墙同时放行 `::` 监听和 ICMPv6（路径 MTU 发现）。
- 内嵌 TURN 若位于 NAT 后，还需端口映射；生产建议独立公网 TURN。

## 7. systemd

`/etc/systemd/system/openmeet.service`：

```ini
[Unit]
Description=OpenMeet Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=openmeet
Group=openmeet
WorkingDirectory=/opt/openmeet
EnvironmentFile=/etc/openmeet.env
ExecStart=/usr/bin/node /opt/openmeet/packages/server/dist/index.mjs
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/var/lib/openmeet
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now openmeet
sudo journalctl -u openmeet -f
```

## 8. 监控与日志

- 健康检查：`GET /api/health` 返回 `{ok:true}`。
- 日志输出到 stdout（systemd/Docker 收集）；默认 info。
- 建议代理层记录状态码与延迟；OpenMeet 不记录聊天、密码、token 与 SDP 正文。
- 告警建议：健康检查失败、5xx 比例、进程重启、磁盘剩余（SQLite/WAL）。

## 9. 数据备份与升级

**备份**

```bash
sudo systemctl stop openmeet
sudo cp -a /var/lib/openmeet "/backup/openmeet-$(date +%F)"
sudo systemctl start openmeet
```

或运行中执行 `PRAGMA wal_checkpoint(TRUNCATE)` 后同时复制数据库与 `-wal/-shm`。

**升级**

1. 备份数据目录。
2. 拉取代码、`npm ci`、`npm run build:server`。
3. 在低峰窗口重启；**进行中的会议会中断**（活跃状态仅存内存）。
4. 验证 `/api/health` 与登录；桌面端协议版本需为 1。

## 10. 容量与扩展

- 单进程单节点；房间状态在内存，不能水平多实例共享。
- 信令开销小，瓶颈通常是连接数与 TURN 带宽。
- 单房间 WebRTC Mesh 建议 ≤ 6 人。更大规模需要 SFU（路线图），不能用增加
  服务端实例解决。
- TURN 建议独立部署、独立带宽；内嵌 TURN 仅适合小规模。

## 11. 常见问题

| 现象 | 排查 |
| --- | --- |
| 登录提示网络错误 | 地址/端口、TLS 证书、反代是否转发 `/api` |
| WebSocket 频繁断开 | 反代 Upgrade 头、读超时、CDN 是否支持长连接 |
| 能进会议但无音视频 | NAT 类型；配置 TURN；临时开启仅中继验证；防火墙 UDP |
| LAN 邀请无法加入 | 主机防火墙放行 TCP 45871+；AP 隔离；IPv6 scope；换 IPv4 端点 |
| 摄像头打不开 | Windows 隐私设置、设备占用、Electron 权限策略 |
| 登录很慢 | 反向代理 DNS、scrypt 资源；检查 CPU 限流 |
| 移动端无法访问 | v0.1 无 Web 客户端；只支持桌面端 |
| 多实例部署后房间丢失 | 不支持多实例共享房间；使用单实例或等待 SFU/共享存储版本 |
