# OpenMeet 互通网关（SIP / H.323）

> 适用于 `@openmeet/gateway` v0.1 ｜ 最后更新：2026-10-23
>
> 本文标注了每一项能力的**验证状态**。已验证的部分给出可复跑的验证手段；未验证的部分明确写出原因，不要当成可用功能部署。

## 1. 为什么要独立进程

OpenMeet 的媒体面是 WebRTC：DTLS-SRTP、Opus/48 kHz、由浏览器持有编解码与抖动缓冲。
电话侧是 RTP/AVP：SDP 协商、G.711 为主、8 kHz、DTMF 走 RFC 2833。
两者必须有人做信令适配 + SRTP↔RTP 转换 + 重采样/转码，这件事不能放进 Electron 客户端：

- 转码与抖动缓冲是常驻 CPU 负载，客户端退出通话就断；
- 一条 SIP trunk 通常服务多个房间，属于服务器侧资源；
- NAT 拓扑不同：网关需要固定的公网/内网媒体地址，客户端不需要。

所以新增 `packages/gateway`，OpenMeet 服务端与客户端**不改动行为**，网关以一个普通参与者的身份加入房间。

## 2. 组件与数据流

```
SIP 话机 / PBX / H.323 网关
        │  SIP/UDP (RFC 3261) + RTP/AVP (G.711 或 Opus/48k) + RFC 2833
        ▼
┌───────────────────────────── packages/gateway ─────────────────────────────┐
│ UdpTransport ──► sip.js UserAgent ──► GatewaySessionDescriptionHandler      │
│                                            │ 选择编码、持有 RtpEndpoint      │
│                                            ▼                                │
│                                       AudioBridge                           │
│                                            │ Opus 直通 / Opus↔PCM↔G.711      │
│                                            ▼                                │
│                        RoomParticipant (werift: ICE + DTLS-SRTP + Opus)     │
└───────────────────────────────┬──────────────────────────────┬──────────────┘
                                │ HTTP /api/rooms/:code/join   │ WS /ws 信令
                                ▼                              ▼
                        OpenMeet 服务端  ◄──────►  Electron 客户端（mesh 成员）
```

网关在房间里就是一个普通成员：有 `peerId`、显示名（如「电话接入」）、媒体状态，
受同样的访问控制约束（房间密码、等候室、锁定、被主持者静音/移出）。

## 3. 编码策略

| 远端提供 | 网关选择 | 媒体路径 | 代价 |
| --- | --- | --- | --- |
| `opus/48000`（RFC 7587） | Opus | 载荷直通，只重写 RTP 头与载荷类型 | 无转码 |
| `PCMU/8000` | μ-law | Opus 解码 → 48k→8k 重采样 → μ-law；反向同理 | 每帧一次编解码 |
| `PCMA/8000` | A-law | 同上 | 每帧一次编解码 |
| 其它（G729/GSM…） | 无 | 回 488 Not Acceptable | — |

优先 Opus 是有意的：现代软电话与 Asterisk/FreeSWITCH 默认都带 Opus，能整条链路免转码。

DTMF：入向解析 RFC 2833 事件（含 onset/end）；出向由 `sendDtmf()` 成对发送。

## 4. 验证状态

### 已验证（有可复跑手段）

| 结论 | 证据 |
| --- | --- |
| werift 在 Node 下完成 ICE + DTLS-SRTP 并搬运 RTP | `node scripts/probe-werift.mjs` |
| **werift 与 Chromium 真实 WebRTC 栈互通**，双向媒体 | `node scripts/probe-browser.mjs <cdpPort>`：双向 `connected`、ICE `succeeded`、Chromium→werift 157 包、werift→Chromium 158 包且触发 `ontrack` |

| sip.js 可在 Node 上用自建 UDP transport 完成真实事务 | `node scripts/probe-sip.mjs`：MESSAGE 送达、双方 transport `connected` |

| Opus↔PCM↔G.711 链路保真 | `test/opus.test.ts`：Goertzel 频域断言（440 Hz 保音高、48k→8k 保 400 Hz、全链路后 300 Hz 仍主导） |
| SDP 解析/构造、编码选择、RTP 端点、DTMF | `test/sdp`、`test/media`、`test/sip.test.ts` 的 codec selection |

### 未验证 / 未完成

| 项 | 状态与原因 |
| --- | --- |
| **SIP 入呼接通** | 未完成。INVITE 能到达网关，但 `onIncoming` 触发时 sip.js 还没把 `sessionDescriptionHandler` 挂到会话上，`accept()` 赶在状态机进入 `Completed` 之后，对话终止。对应测试以 `skip` 标注原因保留在 `test/sip.test.ts`。 |

| 网关打包与部署 | 只有库构建（`dist/index.mjs`），没有可运行 CLI，因为入呼尚未打通。 |

## 5. H.323 边界

**不实现 H.323 协议栈**，理由：H.323 需要 H.225/Q.931、H.245/RAS 与 ASN.1 PER 编解码，
纯 JS 自研是多周量级且几乎无法在没有真实终端的情况下验证；本机也没有 PTLib/OpenH323 或容器可用。

通行且可落地的做法是把 H.323 交给专用网关（Polycom/RADVISION/ Cisco 或开源 OpenH323/PTLib 网关），
让它把 H.323 呼叫落成 **SIP + G.711/Opus**，再由本网关接入：

```
H.323 终端 ──H.225/H.245──► H.323↔SIP 网关 ──SIP/UDP + RTP──► OpenMeet 网关 ──► 房间
```

对接该边界需要确认的项（等 SIP 侧打通后逐条验证）：

| 事项 | 说明 |
| --- | --- |
| 信令 | SIP over UDP，可选 TCP；H.323 的 Gatekeeper 路由由外部网关承担 |
| 音频 | H.723.1/G.711 → 映射为 PCMU/PCMA；若对端支持 Opus 则走直通 |
| 内容共享 | H.239 BFCP 类共享无法映射到 WebRTC 的第二路视频，会丢失；需要共享时改用客户端入会 |
| 视频 | 不互通（见上表） |
| 号码映射 | 外部网关把 E.164/H.323 alias 翻译成 SIP Request-URI，再由网关按 `externalDialIn` 找房间 |

## 6. 房间映射（规划，尚未落地）

设计目标是在服务端 `rooms` 增加 `externalDialIn`（SIP 分机号 / 被叫前缀），
网关收到 INVITE 后按 Request-URI 查表决定进哪个房间，并支持主持人从客户端查看/断开外部来电。
当前网关以「显式指定房间号 + 邀请令牌」方式加入（见 `scripts/e2e-room.ts`），
服务端的 `externalDialIn` 字段与查询接口尚未实现，属于下一步。

## 7. 复跑验证

```bash
npm run typecheck && npm test          # 服务端 9 项 + 网关 26 项（1 项按原因跳过）
npm run build:gateway

# 依赖层
node packages/gateway/scripts/probe-werift.mjs
node packages/gateway/scripts/probe-sip.mjs

# 与真实 Chromium 互通（需先启动带 --remote-debugging-port 的客户端）
node packages/gateway/scripts/probe-browser.mjs 9333

# 全链路（自行拉起服务端 + 客户端 + 网关）
node packages/gateway/scripts/e2e-bridge.mjs
```

`e2e-bridge.mjs` 会自建临时数据目录与独立 user-data-dir，不影响本机其它服务。
