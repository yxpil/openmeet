# 无服务器局域网直连（设计）

> 状态：**协议与节点内核已实现并有测试**；渲染层接入尚未完成。
> 本文记录已确定的契约，避免实现 UI 时另起一套真相。

## 1. 目标与边界

现有"局域网会议"仍要求**主机进程在线并跑内嵌服务**：主机离开，会议就散。
本模式要的是同一网段内**没有任何协调者**的会议——每台客户端自己发现彼此、
自己承载信令、直接建立 WebRTC mesh。

明确不做：跨互联网无服务器开会。没有 STUN 拿不到公网地址，没有 TURN 打不通对称 NAT；
那属于另一类取舍（第三方信令或自建服务），不在此模式内。

## 2. 房间身份：口令不出本机

```
roomId = HMAC-SHA256(key = passphrase, msg = "om-p2p-v1:" + 规范化(code)).hex[0..32]
```

- 广播里只出现 `roomId`，不出现口令，也不出现明文房间号；旁听者既进不来，也认不出这是哪场会。
- 加入者必须能算出同样的 `roomId` 才能通过 `hello` 校验 → 口令即准入。
- 规范化与房间码规则一致（去分隔符、转大写），`ABC-DEF-GHI` 与 `abcdef ghi` 同义。

**已知弱点（v1 有意接受，需在 UI 与文档中说明）**：`roomId` 是**持有即生效**的凭据，
拿到它的人可以伪造广播。它等价于"房间口令"，但不含时效与成员签名，
因此不防重放——局域网内信任模型下可接受，跨信任域请改用服务器会议。

## 3. 发现与建链

| 环节 | 做法 |
| --- | --- |
| 宣告 | 每 2 秒向 `255.255.255.255`、本机子网定向广播、`239.255.45.87` 组播发 UDP beacon；组播不可用时自动退化为广播 |
| 内容 | `{m:'om-p2p', v, room, peerId, name, host, port, kind, sentAt}` |
| 建链方向 | **peerId 较小的一方主动连**，保证全图只有一条 TCP 连接，不会双向重复 |
| 鉴权 | 首帧必须是 `hello` 且 `room` 与本机推导一致，否则以 `4001 room mismatch` 关闭 |
| 名册扩散 | `welcome` 携带现有成员 + `referral` 转发，新成员一次拿齐全图，mesh 自动闭合 |
| 离开 | 关闭时发 `bye`（UDP）与 `leave`（WS）；只发 `bye` 失败也没关系 |
| 掉线 | 7 秒未见任何 beacon/链路活动即从名册剔除并通知（模拟机器直接断电） |

链路消息类型：`hello / welcome / referral / signal / media / chat / hand / mute-request / leave`。

## 4. 与现有会议逻辑的关系

`MeetingClient` 与协调者的全部耦合只有三处：连接+握手、`send(ClientMessage)`、
`onmessage(ServerMessage)`。因此本模式**不重写 mesh**，而是实现一个传输适配器：

```
LanP2pTransport  ──把 P2P 事件合成为──▶  ServerMessage 形状（welcome / peer.join /
                                          peer.leave / signal / chat / room.update）
                                        ▼
                              现有 MeetingClient 与渲染层不变
```

这样音视频协商、ICE、远端流槽位（见 docs/02 §5.3）等已验证逻辑直接复用，
回归风险集中在适配器本身。

## 5. 权限模型的退化（必须写进 UI）

没有协调者就没有强制方：

| 能力 | 服务器会议 | 无服务器直连 |
| --- | --- | --- |
| 准入 | 口令 + 等候室由服务端强制 | 仅口令（`roomId` 校验），**无等候室** |
| 锁定房间 | 服务端拒绝 | 只能拒绝新 `hello`，已进名册者无法追溯 |
| 静音他人 | 服务端下发 `moderation` | `mute-request` 只是**请求**，对端可自行忽略 |
| 移出成员 | 服务端断开其信令 | 无法强制，只能各自断链 |
| 主持者移交 | 服务端记录 | 无权威状态，不做主持者概念 |
| 会议历史/聊天留存 | 本机 SQLite | 同样可存本机，但无服务端备份 |

因此该模式定位是**同信任域内的临时会议**（同一间会议室、同一办公室），
不是对外公开会议的替代品。

## 6. 实现进度

已完成并有测试（`packages/desktop/test/p2p-node.test.ts`，4 项）：

- `deriveRoomId` 规范化与区分度（口令不同→摘要不同；分隔符无关）
- 双节点发现、单方向建链、`signal` 双向送达、`chat` 送达、`media` 状态扩散
- **口令错误的节点无法加入名册**
- 无 bye 消失的对端在超时后被剔除

尚未完成：

- 主进程 IPC 与预加载桥（`p2p:start/join/signal/chat/state` + 事件回推）
- `LanP2pTransport` 适配器与 `MeetingClient` 的传输抽取
- 首页入口、预览页在无服务器模式下的入会路径（不经过 HTTP join，没有 ticket）
- 真机双客户端端到端验证（含组播被过滤的网络环境）
- 多网卡选择：当前取第一个非回环 IPv4，未让用户挑选
